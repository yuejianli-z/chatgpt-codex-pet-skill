# 带标注的动作与注视大板

用于用户请求的大展示板。这是沟通/设计作品，不自动等于导入图集或通过验收的动画。保持已批准身份，只处理本次指定角色和范围。

## 请求格式也是验收条件

记录用户是否明确要求或引用了动态大板，不能静默降级成静态设计表。动态大板所宣称的每条动作都必须包含实际生成源帧构成的状态内角色运动。九张静姿轮播、放大缩小或整图平移不能满足要求。静态姿势板仅是阶段设计预览，动图交付仍待完成。

核验最终编码 GIF/视频承诺的源帧覆盖、各态可读运动、时序和循环回接。十六姿态注视扫动如实标注，不证明连续插值或宿主指针跟随。不能因为标注、静姿或编码命令已存在，就称动图就绪。

## 紧凑双语展示

一个紧凑组合大板合并真实动作循环、单体追视和本次要求的全身静态视角。删除底部长说明与无用留白，不删除要求的内容。比例和视角数量来自最新实际核对的布局。概念图只提供版式，角色使用另行批准的源稿。静态代表帧总览是同版式的另一种呈现，不是动画的替代。

图内所有有意义文字均为中英对应：角色名、分区、动作短词、单独的状态或非业务用途、文字方向提示。优先准确短词或必要短语，不堆长句。使用核实名称或明确标明的昵称音译/描述性译名，不编造官方英文。例如“探爪 / Probe”是表演，“处理中 / Running”是拟表达含义；这个例子不是通用动作处方。非业务轨道保留移动、招呼等用途，不硬塞入四业务态。

来源/改编、理由/区别、推断补全、精确界面触发证据或未知、完整覆盖放配套 manifest 或交付说明。长说明从图内移出，不是从交付中删去；简洁排版也不能掩盖不实承诺。

当前编辑画册示例：左侧大追视，左下四个全身视角排一行，右侧 3×3 动作。这是当前项目选择，不是永久规范或宿主图集布局。画布、viewport、间距和文字基线另存版式配置。对齐容器但不拉伸角色、不逐帧缩放、不抹掉跳跃高度。身体左/右视角需看实际像素确认，不能只信标签。

## 大板记录（配套 manifest，不全印在图中）

- 角色 / 正式展示名 / 已批准参考版本：
- 精确目标界面及客户端/版本；未核实就写未知：
- 本板范围：代表关键姿势 / 完整有序源帧 / 已解码动画证据。按实际完成范围选，不按最终愿望选：
- 目录及依据：业务状态___；动作轨道___，有效动作帧___；注视方向___；缺失/部分覆盖___：
- 数量分开：注明日期的 Pets 例子是桌面 4 业务状态、9 轨道/57 动作格、v2 的 16 注视样本。九张代表动作图不等于57帧或九段通过的循环。大图更大不代表覆盖更全。

## 动作区：每条必需轨道有清楚标签

每个面板只印简洁的中英动作词和含义标签。下表全部字段记录在对应 manifest，让证据可追踪，但不把小字塞满图片。

| 字段 | 必填内容 |
|---|---|
| 轨道与状态含义 | 技术轨道；拟表达的业务意义或非业务事件。已核实产品事实与拟议图行绑定分开。 |
| 选定动作 | 一个具体角色表演，不是手势菜单。 |
| 来源路线 | 个体/物种自然行为；已核实同版本 IP/创作者动作；或通用兜底。这是来源路线，不是状态。 |
| 证据/改编 | 来源链接或私有参考代号、原情境、实际看到了什么、本案改了什么。比喻不包装成生物事实或虚构原作设定。 |
| 理由与区分 | 为什么这只角色能做、传达什么、最易混淆哪一态、可见区别在哪里。自然或知名动作仍需说明适配理由。 |
| 触发状态 | 精确界面；操作及图行绑定的核实依据/日期，或**未知**。只核实操作时写“操作已知，动画绑定未知”。 |
| 本板展示覆盖 | 代表关键姿势，或带实际帧号/数量的完整有序序列。标出缺少阶段与尚未生成帧。 |
| 验收范围 | 拟议 / 已生成 / 已按实际尺寸看图 / 已看完整循环 / 已观察原生运行，分别给具体证据，不能统称“完成”。 |

每轨只展示一张时，动作区标题写**动作设计关键姿势**，不写“完整九段动画”。文字标注放在角色美术外，避免误认为精灵内容。完整序列应展示顺序和进入/保持/回接；静态帧列仍不能证明播放节奏或运行触发。

## 注视区：单体展示，方向样本单独记录

- 同一注册角色依次看向每个目标方向，配当前目标/角度标记；不能换成多只角色网格、全身转台或实时跟随承诺。配套记录按适配器坐标列齐方向。注明日期的 v2 以 000 向上、090 屏幕右、180 向下、270 屏幕左为基准，包含全部十六个 22.5° 步进。
- 每格标预期角度/方向和实际瞄准标志；不要混入任务状态标签。
- 同比例、共用注册展示已批准身份，不把头/注视姿态画成整个人物转台。
- 缺失、重复、含糊方向明说；十六格有像素不证明十六方向全对。
- 指针跟随、角度选取、覆盖动作行的优先级、混合：记录精确界面证据或**未知**。注视大板不证明这些运行行为。

## 展示前

核对所有有意义标签均双语、动作与含义分开、实际尺寸文字无截断；包含本次要求的身体视角，没有底部长说明或多余留白；数量和单位正确；每动作配套记录有含义/动作/来源/理由/触发状态；关键姿势与完整循环的范围清楚；注视方向标签齐全；无猜造鼠标绑定；身份和最新批准范围保留。未决设计选择显式保留。既审文字也审画面，不能用说明替不可读的手势通过。

## 混用源素材前的跨行尺度注册

新条带通过自己的抽帧/行内检查，不代表能与旧图集按同一名义倍率直接混用。提取时的尺度或锚点可能不同。验收组合图集或展示板前，必须比较获准待机/参考行与每个新行之间的状态切换。

以获准的中立姿态或可比姿态作为身份锚，在相同物理尺度下比较稳定的头部、躯干特征尺寸、身体比例，以及预期脚底/接触或悬浮锚。动作抬爪、张翼、摆尾或跳离地面都可能增大整幅bbox高度，因此bbox不能单独代表角色尺度。没有可比姿态时记录不确定性，用多个稳定特征核对，不能强行等高。

保留原始提取帧与提取尺度/平移。若整组源一致偏大或偏小，对该完整组应用一个有记录的共享尺度和注册变换，按参考接触锚对齐。同组各帧及共用该源注册的动作行保持同一变换。禁止逐帧按自身bbox拟合、把所有姿态变成一样高或抹掉腾空位移。若组内尺度不一致，应修正提取或源美术，不能用逐帧拟合掩盖。

记录源版本/hash、原提取变换、中立参考帧与特征点、带单位的特征尺寸、最终整组尺度/平移、锚点、影响帧和最终注册源hash。复查待机→每个改动行→待机、原生尺寸身份、支撑/腾空运动和循环接缝；组合编码后另看实际输出。数字尺度修正只证明注册处理，不自动判断解剖、像不像或动作语义。
