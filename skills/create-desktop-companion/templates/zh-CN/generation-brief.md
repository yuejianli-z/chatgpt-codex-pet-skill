# 已选动作生成简报

未来生成模板，不是真实执行记录。依据已批准动作提案填写，删除不适用指令。不得用本模板改写历史已执行提示词。

- 角色 / 外观参考 / 受保护身份与材质：
- 宿主状态键 / 已核实系统含义：
- 精确界面 / 客户端版本；触发及图行绑定有证据已核实，或未知：
- 输出是代表关键姿势还是完整有序动作行；应有帧与实际生成帧分别记录：
- 唯一选定动作，具体描述（不能写“思考或打字或扫描”菜单）：
- 证据标签与源行为；哪些为改编而非原作：
- 注意目标 / 请求对象及主要可读信号：
- 活动部件 / 固定锚点 / 各主体部件归属：
- 必需结构与已有装备；不得出现的缺失特征：
- 序列类型与来自适配器的源帧预算：

| 顺序相位 / 实际帧 | 精确运动与停留 | 持续可见的状态线索 | 要避免的最接近错误解读 |
| --- | --- | --- | --- |
| 进入 | | | |
| 活的保持 / 事件动作 | | | |
| 循环返回 / 事件恢复 | | | |

- 持续思考：说明每个相位及循环回接如何仍在思考，而非待机/招呼/请求。
- 请求：写明向用户求回应及耐心等待的信号，不表现已经获批。
- 事件：写明预备、接触/支撑及恢复，不能暗示相反任务结果。
- 镜头、共用比例/配准、允许形变、边缘/背景及适配器约束：
- 源稿与最终帧的身份/语义审查计划：
- 已删除冲突通用子句，简报只剩所选动作：
- 用户批准动作范围 / 未执行或执行日期及不可改写记录：

生成器负责实现这段表演，不负责决定状态本应表达什么。若所选动作不适合结构或帧预算，应回到动作设计，不能临时增添身体部件或换成另一手势。

- 最终请求格式及参考：若要求动图，此源任务须贡献真实状态内动作；关键姿势预览不满足最终动画交付。

- 双语组合展示：真实动作、单体追视和本次要求的身体视角。动作词与用途标签均中英对应，详细证据放配套说明。版式来源与角色身份源分开，交代表关键帧总览及私有复现包。
