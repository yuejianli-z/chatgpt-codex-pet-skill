# 逐阶段学习台账

每个实际经历的阶段记录增量。不得为填表编造失败：“未发现”也须注明检查范围。使用项目内代号和脱敏公开摘要。保留原失败日志与实际执行输入。

## 条目（每项发现复制一份）
- 条目代号 / 案例代号 / 阶段 / 日期：
- 输入证据：参考 / 版本 / 哈希；实际查看图像 / 帧 / 时间范围；观察方法及限制：
- 失败或优化机会：观察结果与预期标准的差异；或未发现及检查范围：
- 原因假设：支持证据、不确定性与其他解释：
- 有边界修复：确切变化、保留的批准层 / 格、授权范围、尝试次数 / 预算、停止 / 切换路线条件：
- 验证：下表中的实际执行与结果；新版本及保留的失败执行引用：
- 结果：verified / unresolved；未解决缺陷或阻塞证据：
- 可泛化规则：精确表述、适用条件、排除项、已落实规则 / 模板 / 检查的位置：
- 泛化状态：supported_within_case / proposed_transfer / cross_case_verified：
- 证据状态：observed / untested / inconclusive：
- 回归测试 / 场景引用与实际执行结果：

必需链路：阶段证据 → 失败 / 机会 → 假设 → 有边界修复 → 已验证或未解决结果 → 有适用范围的规则 → 回归测试。缺环节时记录不确定性，不补写成功结论。

## 完整性检查
- [ ] 每个实际阶段均有记录；不虚构未经历阶段。
- [ ] 假设与观察区分；修复范围有边界。
- [ ] 保留失败报告与原提示；纠正为新补注 / 新执行。
- [ ] 验证结果引用实际证据；阻塞与未测保持明确。
- [ ] 不把人工视觉场景标成自动测试通过。
- [ ] 没有跨案例证据时，不把单例发现标为 cross_case_verified。
- [ ] 每项保留的学习落实到具体规则 / 模板 / 检查与回归场景。
- [ ] 公开副本排除未核清的私人输入、标识、路径与案例图片。
