# Labeled action and gaze board

Use for a requested large visual board. This is a communication/design artifact, not automatically an import atlas or tested animation. Keep approved visual identity; use only the character and affected scope requested.

## Requested format is part of acceptance

Record whether the user requested or referenced an animated board. Do not silently downgrade it to a static design sheet. For an animated board, every advertised action must contain genuine within-state character motion from its generated frames. Switching nine still poses, zooming or translating the entire picture does not satisfy this. A static pose board is an interim design preview only; the motion deliverable remains pending.

Verify the final encoded GIF/video has the promised source-frame coverage, readable individual state motion, timing and cycle return. Label a sixteen-pose gaze sweep as such; it does not prove continuous gaze interpolation or host pointer tracking. Do not mark animation ready merely because captions, still poses or an encoder command exist.

## Compact bilingual presentation

Use one compact combined board with genuine action loops, a single-character gaze sequence and the currently requested full-body views. Remove dense footnotes and unused margins, not requested content. Configure ratio and view count from the latest visually inspected layout. A concept supplies composition only; use separately approved character sources. The representative static overview is a separate rendition of this same composition, not a substitute for motion.

Every meaningful in-image label has Chinese and English: character name, section titles, action word, separate state or non-business purpose, and verbal direction cues. Prefer a precise word or short phrase, not a long sentence. Use verified names or clearly identified nickname transliterations/descriptive translations, never invented official names. For example, “探爪 / Probe” names a performance while “处理中 / Running” names its intended meaning; this example is not a universal action prescription. Non-business tracks retain labels such as movement or greeting instead of being forced into the four business statuses.

Keep source/adaptation, rationale/distinctness, inferred completion, exact-surface trigger evidence or unknown, and full coverage in the companion manifest or delivery note. Omit those lengthy notes from the image, not from the deliverable. Do not hide unsupported claims behind clean typography.

Current editorial example: large gaze at left, four full-body views in one row below, and a 3×3 action grid at right. This is the present project choice, not a universal rule or host atlas layout. Record actual canvas dimensions, viewports, gutters and text baselines in a separate layout config. Align containers without stretching characters, independently scaling each frame, or erasing jump height. Recheck left/right view meaning in the actual pixels.

## Board record (companion manifest; not all printed in the image)

- Character / formal display name / approved reference version:
- Exact destination surface and client/version; unknown if unverified:
- Board scope: representative key poses / complete ordered source sequences / decoded animation proof. Choose the actual scope, not the desired final scope:
- Catalog and source: business statuses ___; action tracks ___ with ___ active frames; gaze directions ___; missing/partial coverage ___:
- Counts are separate: the dated Pets example has 4 desktop business statuses, 9 tracks/57 action frames, and 16 v2 gaze samples. Nine representative action pictures are not 57 frames or nine validated loops. A larger board is not automatically more complete.

## Action section: one clearly labeled panel per required track

Print only the concise bilingual action and meaning labels on each panel. Record all fields below in the associated manifest so the evidence remains traceable without filling the image with small text.

| Field | Required content |
|---|---|
| Track and state meaning | Technical track; intended business meaning or non-business event. Separate verified product fact from proposed row binding. |
| Selected action | One concrete character performance, not a gesture menu. |
| Source route | Natural individual/species behavior; verified same-version IP/creator performance; or conventional fallback. These are sourcing routes, not states. |
| Evidence/adaptation | Source link or private reference label, original context, what was actually seen, and what this proposal changes. Never label a metaphor as biological fact or invented canon. |
| Rationale and distinction | Why this actor can perform it, what it communicates, nearest confusable state, and visible difference. A natural or famous action still needs this justification. |
| Trigger status | Exact target surface; verified operation and row binding with source/date, or **unknown**. If only the operation is verified, say “operation known; animation binding unknown.” |
| Displayed coverage | Representative key pose(s), or complete ordered sequence with actual frame indices/count. Mark missing phases and ungenerated frames. |
| Acceptance scope | Proposed / generated / reviewed at target size / whole-cycle watched / runtime observed, with concrete evidence. Do not collapse these into “done.” |

If only one pose per track is shown, title the section **action-design key poses**, not “complete nine animations.” Annotate outside the character art so labels are not mistaken for sprite content. For a full sequence, expose order and entry/hold/return; still image sequences do not establish timing or runtime triggers.

## Gaze section: one character, separate directional samples

- Animate one registered character looking successively toward each required direction, with a current target/angle cue. Do not substitute a grid of separate characters, a body turntable, or a live-tracking claim. List every required direction in the companion record using the adapter's coordinate system. Dated v2 uses 000 up, 090 screen-right, 180 down, 270 screen-left, with all sixteen 22.5° steps.
- Label expected angle/direction and observed aiming landmarks per sample. Keep task-state labels out of this section.
- Show approved identity at shared scale/registration. Do not turn a head/gaze set into a whole-character turntable.
- Mark missing, repeated or ambiguous directions. Sixteen occupied cells are not proof of sixteen correct directions.
- Pointer tracking, angle selection, priority over action rows and blending: exact-target evidence or **unknown**. A gaze pose board does not prove those runtime behaviors.

## Before showing the board

Check: all meaningful labels are bilingual and action/meaning are separate; actual-size text has no clipping; requested body views included; no dense footer or excess whitespace; correct counts and units; every action has meaning/action/source/reason/trigger status in the companion record; clear pose-versus-loop scope; all required gaze labels; no invented mouse binding; approved identity and latest scoped request preserved. Keep unanswered design choices visible. Review the actual artwork as well as captions: words cannot rescue an unreadable gesture.

## Cross-row scale registration before mixing sources

A newly extracted strip passing its own row checks does not mean it can be mixed with an older atlas at the same nominal multiplier. Extraction may have used a different scale or anchor. Review state changes between the approved idle/reference row and every new row before accepting the combined atlas or showcase.

Use an approved neutral or comparable pose as the identity anchor. Compare stable head and torso feature dimensions, body proportions and the intended foot/contact or hover anchor at a shared physical scale. A frame's overall bounding-box height may grow because a paw, wing or tail extends or a jump leaves the ground; it is not a reliable standalone measure of identity scale. If no comparable pose exists, record that uncertainty and use multiple stable landmarks rather than forcing equal height.

Preserve the original extracted frames and their extraction scale/translation. When a source group is consistently oversized or undersized, apply one documented shared scale and registration transform to that complete group, aligned to the reference contact anchor. Keep the same transform across its frames and any rows that share that source registration. Do not fit each frame to its own bounding box, normalize all poses to identical height, or erase airborne displacement. If the mismatch is inconsistent within a group, correct the extraction or source artwork rather than concealing it with per-frame fitting.

Record source version/hash, original extraction transform, reference neutral frame and landmarks, measured feature sizes with units, selected group scale/translation, anchor, affected frames, and final registered source hashes. Recheck idle → each changed row → idle, identity at normal display size, contact/airborne motion, and loop seams. Separately inspect the actual encoded output after composition. A numeric scale correction is evidence of registration, not an automatic verdict on anatomy, likeness or semantic quality.
