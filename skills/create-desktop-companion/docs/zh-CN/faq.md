# 常见问题

[English](../en/faq.md)

## 这是桌宠软件吗？

不是。它是制作 Skill 和本地审阅工具，帮助助手规划、使用可用工具制作并检查素材。原生显示、安装与事件来自宿主应用。

## 为什么仓库名与 Skill 名不同？

GitHub 仓库名为 `chatgpt-codex-pet-skill`，Skill 声明名称为 `create-desktop-companion`。安装时将完整目录命名为后者，`SKILL.md` 应直接位于其中。

## 需要 API 密钥吗？

附带诊断、合成示例和离线查看器不需要。新图像使用你选择的服务及其访问权限和条款。本仓库不收集凭据。

## 可以用自己的宠物照片或已有角色吗？

可以用于获准的项目。保留个体花纹，区分已观察细节与未见部分的推断。持有参考或认可作品不等于获得再分发许可；未经许可不要将私人参考上传外部服务。

## 支持 Claude、Codex、Cursor 等助手吗？

工作方法基于 Markdown，文档给出了 Codex 和 Claude Code 的本地安装路径。能加载 Skill、能生成图像和能原生显示桌宠是不同能力。不附跨 Agent 运行适配器，见[兼容性](compatibility.md)。

## 为什么查看器拒绝我的图集？

检查格式、文件大小与精确尺寸：PNG/WebP，最大 20 MiB，v1 为 1536×1872，v2 为 1536×2288。不要直接把其他布局缩放成这个尺寸，图格含义与留白也必须匹配。其他契约需要适配；查看器通过也不保证宿主接受。

## 查看器能强制切换已安装桌宠的状态吗？

不能。它读取本地图集并模拟播放。实际状态触发、时序和指针行为需要在目标客户端观察。十六个注视姿态不是十六种任务状态。

## 检查通过是否代表角色做好了？

不代表。机器检查针对记录、几何、时序或像素；身份相似度、动作含义、方向可读性与观看舒适度仍需视觉审阅。未填写完整的模板应当失败，不能冒充真实证据。

## 为什么重复运行示例会失败？

`make_test_fixture.py` 拒绝覆盖已有 `geometry-test.gif`，请选新的输出目录。运行工具前保留源文件并核对输出路径。

## 可以做 GIF 或视频展示吗？

工作方法提供规划与审阅要求，但不附完整角色展示板/视频渲染器。使用自己的合成工具，保留源时序并检查最终编码文件。静态姿势幻灯片不能证明动作内部有真实动画。

## 演示图片也采用 MIT 许可吗？

只有来源声明明确涵盖的素材才是。见[素材政策](../../ASSET-POLICY.zh-CN.md)及素材目录说明。工具包的 MIT 许可不授予第三方角色、照片或生成项目作品的权利。
