# 运行状态证据

[English](../en/runtime-state-evidence.md)

## 先写清界面，再谈触发

“ChatGPT 宠物”不是精确运行目标。记录产品、客户端/版本、**界面位置**、日期及证据，至少分开：

| 目标界面 | 证据边界 |
|---|---|
| 桌面悬浮宠物/浮层 | 产品公开文档描述其业务状态和控件。拖拽能改变位置，不证明会播放哪一行。 |
| 桌面聊天内或页头头像 | 即使是同一个角色，也不能沿用悬浮宠物的触发、注视机制或优先级；逐界面核实，否则未知。 |
| 网页 Work 聊天内宠物 | 公开 Pets 页面将其与桌面浮层/活动托盘区分；该入口的格式和交互另核实。 |
| Codex CLI | 官方源码只能证明对应 CLI 的映射，不是桌面页头或 Dot 的实现。 |
| 官方文档网页里的互动示例 | 示例事件代码只证明该嵌入演示，不能证明已安装客户端的行为。 |

每条拟议动作都写**触发已知/未知**、证据类型（产品文档、精确界面观察或对应实现）、适用版本/范围和剩余未知。证据可能只证明操作，不证明动画：“拖动改变位置”不等于 `running-left/right`；点击打开控件不等于 `jumping`；有十六注视格不等于已实现指针跟随或注视优先。不能从素材名猜 hover、单击、双击或拖动绑定。

## 三种数量，不是一套状态机

以下为官方页面的证据：

1. **四种桌面业务状态。** [官方 Pets 产品页](https://learn.chatgpt.com/docs/pets#understand-pet-status)定义 Running 为聊天正在工作，Needs input 为需要批准/回答/决定，Ready 为已完成且还有未读活动，Blocked 为失败/系统错误。多聊天优先级为输入、受阻、就绪、运行。这不证明每个界面具体播放哪一行。
2. **九条创作动画轨道 / 57 个有效动作格。** 已查制作适配器使用下表目录。帧数是素材预算，不是时长、概率或鼠标事件数。
3. **v2 的十六个注视姿态。** 每隔 22.5° 顺时针采样，不是十六种业务状态或十六段完整动作。完整 v2 共 73 个有效格；说明某角色覆盖前先查实际保存文件。有像素或像素互异不自动证明注视含义正确。

| 轨道 | 帧数 | 创作目的，不是已核实的触发 | 精确目标界面的触发/绑定 |
|---|---:|---|---|
| idle | 6 | 安静待机 | 单独取得证据前为未知 |
| running-right | 8 | 右向移动 | 单独取得证据前为未知 |
| running-left | 8 | 左向移动 | 单独取得证据前为未知 |
| waving | 4 | 招呼/吸引注意 | 单独取得证据前为未知 |
| jumping | 5 | 预备、离地、落回 | 单独取得证据前为未知 |
| failed | 8 | 失败/受阻反应 | 单独取得证据前为未知 |
| waiting | 6 | 向用户请求输入/批准 | 单独取得证据前为未知 |
| running | 6 | 任务处理，不是脚跑 | 单独取得证据前为未知 |
| review | 6 | 完成输出查看/兼容就绪的表演 | 单独取得证据前为未知 |

这是创作目录，**不是已经证明的通用九态运行状态机**。产品事实、拟议表演、运行绑定分别记录。兼容 Ready 的动作应显出工作已结束、成果可以看了；持续校对会误示仍在处理。旧制作文字中的“检查已完成输出”不能覆盖公开产品语义。CLI 的 `Review → Ready` 证据仍只适用于 CLI。

公开网页的上传段落与已查 v2 制作路径记录了不同/较旧布局。不能静默合成“所有端统一规格”，也不能仅凭另一个入口写 v1 就否定已核实的存储 v2；核对目标入口并明说差异。

## 创作像素、宿主播放和状态文案分别判断

图集行只定义画出的像素；触发、播放时长、循环、回退与视线优先级由宿主决定。气泡或提示文字描述任务状态，不能当作当前精灵行的可靠读数。不能因为工作很常见，就把“常驻形态”安排到 `running` 并承诺经常出现。已记录的Pets状态语义中，`waiting` 指等待用户批准、帮助或输入，不是泛指加载或所有长任务；须核对目标适配器，不能擅自扩大含义。

单张截图只证明该瞬间可见外形和文案。没有精确源格匹配或播放遥测，就不能唯一确定是idle、gaze或其他相似单元，不能复原切换过程、测量驻留或证明故障原因。记录表面不一致，但不要把假设写成已确认客户端缺陷。

“主要形态占大部分时间”“常见”或95%等占比，在真实目标客户端测量前都只是设计目标。记录图集hash、客户端及版本、观察时段、代表性任务/交互条件、各形态可见时长，以及歧义或无法分类的时段；说明分母和测量方法。有限样本不能保证随机概率。离线帧数、模拟循环及源行名称都不能证明实际占比。

未验证受支持的实时状态触发API时，强制触发覆盖保持未知；不能把所附离线控制器说成已安装行为验收。排查时保留已批准作品，不自动重画或重新分配形态来规避问题。若宿主限制确实要求艺术取舍，先说明影响并取得该范围批准。尊重用户拒绝预览的选择，未请求时不要再发送新预览附件。

### 相关报告，不是已确认诊断

2026-10-19核查：Codex Desktop一手社区报告[#28995](https://github.com/openai/codex/issues/28995)、[#29196](https://github.com/openai/codex/issues/29196)描述工作动画短暂播放后回到idle，而任务仍继续。[#48536](https://github.com/openai/codex/issues/48536)是增强功能请求，也报告其检查的Windows版本中 `running` 有限播放。这些是限定版本的社区报告，不是官方确认Dot或其他客户端的成因。它们提示应检查宿主播放，但不授权修改应用，也不能证明某张私人截图属于同一原因。

## 后续源图审计与另一个变通实验

后续已上传 v3 图集审计确认事件行位置正确，各行从首帧就含替代形态。这证明素材映射，不证明桌面客户端选中或绘制了对应行。仍没有真实实播证据可证明用户原先报告的形态不出现已修复。

另一个把形态切换放入待机行的实验出现硬切，已单独否决。这些跳变属于新变通方案，不属于此前未改的事件行素材。区分两个症状及版本；不能用失败变通方案诊断原始报告，也不能静默安装。
