# 身份保持的局部修复

[English](../en/focused-repair.md)

当已认可的角色出现局部缺陷（视线姿态、配件或轮廓细节）时，使用本方法。它不要求整只角色重画，也不能改变已经认可的身份。

## 1. 修改前先冻结范围

1. 保留已认可的源素材和所有被拒的候选稿。记录素材哈希、可编辑格、受保护格、身份关键点和配准锚点。
2. 冻结受保护格的已认可像素，而不只是描述它的外观。清理和最终组装之后都要重新核对是否完全相同。
3. 用附着点、尺寸、数量和分支结构来描述小配件。看起来漂亮的替代物，身份也可能是错的。
4. 不要为了让生成更容易，就放大整个头部、头顶或配件。

## 2. 只修最小的连贯单元

常见失败：

- 整个视线重画时，小而有辨识度的细节丢失，或者被放大。
- 局部修复时，细节接到了错误的位置，例如身体高度不对。
- 某一版看起来合理，但仍然过不了强制门禁。

修复方法：

- 先锚定附着点和局部轮廓。先在一个姿态上验证修正，再推广到相关姿态。
- 只改缺陷所需的区域和姿态约束。
- 保留失败的尝试。一个根假设已经失败，就不要反复尝试。
- 某个案例中的具体细节、配色和姿态，不能默认套用到其他角色。

## 3. 解码和配准，不引入额外改动

- 核对当前宿主适配器要求的源抠图颜色。不要替换成其他颜色，也不要把某一种颜色推广到所有宿主。
- 把修正后的姿态配准到已认可的锚点和记录的缩放与偏移。检查是否有意外的格位偏移和裁切。身体、脚部稳定性和配件位置要分别检查。格位完全配准，并不代表新生成的像素与原图相同。
- 只对改动的行做抠图清理。受保护的行从原素材重新插回。
- 不要为了通过检查而修改 alpha、不透明度、强制检查项或阈值。
- 在原始尺寸下，分别用白、灰、黑背景检查清理后的边缘；放大查看用于诊断。干净的蒙版本身不能证明身份或方向可读。

## 4. 把验收分层

1. 对最终文件运行当前的强制结构、抠图和质量门禁。
2. 把每个改动格和已认可的身份逐一对照。
3. 做不带答案的盲审方向判断，之后再和标准答案对比。主审还必须检查身份和边界过渡。盲审方向识别不能替代身份审查。
4. 本地门禁结果、服务端预检、宠物创建或选择、用户可见反馈、完整运行验证，要各自单独记录。选中宠物不能证明所有宿主状态或停留时长。

## 5. 记录遗留限制

如果两个姿态之间的边界仍有明显变化，要把它记为遗留限制。不能写成无缝过渡、长时间观看舒适或完整运行验收。在重新测试之前，每一份后续交接都要保留这条限制。

## 修复检查表

- [ ] 已记录已认可源素材，以及可编辑格和受保护格。
- [ ] 最终组装后，受保护像素的一致性已核对。
- [ ] 每个改动姿态的附着点、比例和身份已核对。
- [ ] 源抠图颜色已核对；清理只限改动格；alpha 已保留。
- [ ] 配准、裁切、身体和脚部，以及原始尺寸下白、灰、黑背景的边缘已检查。
- [ ] 最终文件通过强制门禁；没有绕过，没有修改检查器。
- [ ] 盲审方向结果，以及单独的身份/边界审查，已记录。
- [ ] 创建、选择和用户反馈与运行证据分开记录。
- [ ] 边界过渡和未测试的情境已明确记为限制。
