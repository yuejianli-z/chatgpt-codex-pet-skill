# 先设计动作，再生成动作

[English](../en/action-design.md)

新动作批次或语义重做前使用本分支。除非用户另改范围，已批准的外观、比例、材质、服装和认可动作保持冻结。这是在重新导演动作，不是要求重画所有已保存角色。

## 旧方法缺在哪里

旧流程写了“一个意图”和标志行为，却没有先把角色来源转成具体状态设计。实际生成菜单仍可能写“思考、打字、扫描、忙碌爪子、目的性摆动”，把最核心的动作选择交给图像生成。于是首帧看似像某状态、几何通过或动作行齐全，都可能掩盖整轮语义不成立。已有部分人工细化动作确实有价值；须检查具体版本，不能不看就全盘否定或替换。

## 1. 先按正确来源层级建立动作库

1. **真实动物或个人宠物：**有个体习惯时先用真实观察，再参考可靠动物行为、兽医或动物园来源中的物种代表行为。记录身体实际怎么动、发生在什么情境。猫踩奶可能有代表性，但不能据此说它本来就表示“思考”。它不是全局禁止的比喻；若某个具体方案只像舒适/待机而非选定工作线索，就应否决或改选。迁移到界面状态是设计提案，仍须符合自然结构。不能让所有动物长人手或统一挥手。
2. **已知 IP 或可辨认梗角色：**先核对角色及版本，查看官方角色/游戏片段、动画、创作者素材或可追溯原片，找其代表表演。只有真正看过才记录动作相位和时间码。经典攻击、舞蹈、变身不自动适合安静工作或请求批准；取语义合适的部分改编，原片只展示战斗时不能称“原作思考动作”。静态图只能证明姿势/身份，不能证明帧间运动。来源未核实时明确缺口，用标明的拟作兜底，不编造原作动作。
3. **概念或缺少动作来源的头像：**用常见、易懂的状态动作，适配已有结构与气质。思考、请求、休息、失败、复核必须各自有区别的理由。缺来源不等于可以重设计外观，私人头像也不自动属于某 IP。只使用已有肢体、面部、装备和机械功能；真需要新增道具或表达器官时单独提议，不能藏进生成指令。

这是三条**动作来源路线，不是三种状态**。按角色选来源；自然/经典动作不适合界面含义时仍可明确使用兜底。不是片段数量指标，也不是把一个名场面硬塞进所有状态。某状态没有合适自然/经典动作时，可以明确标注兜底。每个动作记录为“已观察行为”“原作表演”“改编提案”或“常见动作兜底”，并注明未知项。

## 2. 每个状态只表达一件事

先读真实宿主契约。技术键、任务文案与可见表演不是同一件事。在注明日期的 Pets 例子中，`running` 是工作，`running-left/right` 才是移动。若本次把工作设计为思考，整个循环就要一直在思考，不能半途切成招呼、耸肩、批准、庆祝或普通待机。

- **待机/发呆：**平静基线与自然维持动作，例如呼吸。不是反复招揽注意、随机巡视，也不是喜欢的手势拼盘。
- **工作/思考：**持续投入一个问题或任务。先选定一个具体动作和稳定注意目标。符合结构的思考线索是供设计者选择的选项，不是一起粘入生成的菜单。回到循环起点时仍保留思考线索，不能每轮都像宣布工作结束。
- **等待输入/请求批准：**面向用户提出耐心请求，然后明显等回应。写清向谁请求、用什么信号。只是静止、睡觉、自顾检查或无目标歪头都不足。这是请求批准，不是表示已经批准。
- **失败/受阻：**尝试中断或泄气，再保持可读的受阻感或有限恢复。不能混成跳跃、普通休息或胜利结束。不要为了状态比喻给真实宠物编造受伤/强烈痛苦。
- **完成后查看/就绪 review：**先确定宿主的实际状态事实。已核对的 Pets 0.1.6 生产契约指检查**已经完成的输出**，也称 ready/completed-output review，不是另一轮尚在处理。可以提议短暂查看结果后进入稳定的就绪姿态；即便结果在画外，也要写清注意对象。竖拇指、点头不是全局禁用：应看实际整段能否读成完成后检查/就绪，而不是只有招呼、庆祝或暗示批准已获授予。与持续工作、等待用户输入拉开，不把持续扫描规定成通用 review 手势。
- **招呼、移动、跳跃等事件：**使用物种/角色专属机制和真实支撑、恢复。经典动作可能更适合这些事件，而不是持续工作。汽车反光变化不等于轮转，车身上下摆不等于合理起跳。宿主必需事件与写实设计矛盾时，说明冲突，取得明确风格化选择，而非假装满足。

**契约证据与边界。** [官方 Pets 产品页](https://learn.chatgpt.com/docs/pets#understand-pet-status)将桌面 Ready 定义为聊天已完成且有未读活动。因此设计“成果好了，可以看了”，不是继续处理。制作说明中“检查已完成输出”可支持短暂注意成果，但不能覆盖产品语义。已核实的 CLI `Review → Ready` 不证明聊天内/页头/悬浮层绑定。阅读[界面与触发证据](runtime-state-evidence.md)，每条未核实绑定写未知。

无脸角色使用相连手臂姿态、头/身朝向和重心，不借眼睛嘴巴。车辆只用已批准设计支持的机械/灯光信号；若不新增视觉约定就无法区分思考与复核，应坦白，而不是给任意晃动车身强加含义。复合角色按主体分配职责，保持关系，同时有一个清晰语义主角。

## 3. 先审动作映射，不重选美术风格

批量重做前，查看已有提示词及最终源动作行。每个角色分清可保留、已证明存在语义缺陷和仍未审阅的部分。提示词想表达什么，不证明成图真表达了什么。精确版本及证据私下保留。

给用户简明[动作提案](../../templates/zh-CN/action-proposal.md)：角色、来源类别、各宿主状态对应动作、为什么这样表达、来源/改编标签，以及改动/保留/未知状态。只把真正的取舍用普通话说明。这是在审动作，不重新打开已批准外观，不让每个角色再走一次风格三选一。尚未获得受影响制作范围的授权时，提案保持待定。后续指令已明确授权按名单逐角色重做时，展示简洁的本角色映射后在该范围内推进，不新增强制等待批准。仅身份/范围实质变化或真正需要用户决定的未决项再确认；逐角色语义检查仍不可省略。

先选能解决最大语义风险的代表样本，通常是容易混淆的待机/思考/请求/复核，再扩展其他行。先做完整批次才发现动作像别的状态，并非合理试验。用户先要大展示板时，按[大板模板](../../templates/zh-CN/action-board.md)标注；每轨一张代表姿势仅证明设计覆盖，不是完整动画覆盖。

## 4. 把选定动作写成具体表演指令

动作选好后使用[生成简报](../../templates/zh-CN/generation-brief.md)，明确唯一动作、目标状态、请求/注意对象、活动与固定部件、顺序相位。直接描述选定运动，删除冲突的通用动作子句，不能在冲突模板后追加“覆盖”。保留真实历史执行提示词，未来简报在执行前标为未执行。

持续状态按“进入线索 → 具有微小变化的保持 → 回到同一语义线索”设计，不必每轮回普通待机。事件可采用“预备 → 动作 → 恢复”，但恢复不能暗示相反的任务结果。真实跨状态转换仍是另一问题，不能为了所有端点中性而抹掉状态含义。

帧预算限制可容纳的表演。应简化所选动作，而不是在六帧里塞入思考、指向、耸肩和微笑。不能为了挽救没设计好的简报临时添加道具、面部或服装变化。

## 5. 按整个循环判断含义

用最终编码动作，在目标显示尺寸下去掉状态标签观看，再与容易混淆的状态并排比较。问角色在做什么、面向谁、解释在哪个相位改变，记录真实观察与含糊段落，不用预设答案引导。只认出首帧不能通过整轮；末帧→首帧既查物理连续，也查语义连续。

对照已选来源和改编边界，判断：是不是这个角色；整个循环是否传达目标状态；不靠文字能否与相邻状态区分。自然行为不必字面携带人的心理状态，但界面比喻要可读、标签要诚实。仍混淆时改动作选择，不改状态名、门禁阈值或审阅答案。

来源保真、结构/身份、状态含义、跨状态区别、整轮一致和实际客户端行为分别下结论。JSON 字段、运动指标、方向检查或上传成功都不能证明这些语义判断。用[状态设计表](../../templates/zh-CN/state-plan.md)及[交付审阅](../../templates/zh-CN/delivery-review.md)保存证据，不编造通过数量。

## 支持这些选择的动画原则

[Frank Thomas 与 Ollie Johnston](https://frankanollie.com/KeysToEmotion.html)强调清楚、简单的角色意图；[Dave Burgess](https://www.animationmentor.com/blog/timing-the-12-basic-principles-of-animation/)说明主姿势需要阅读时间；[Shawn Kelly](https://www.animationmentor.com/blog/why-all-animators-need-to-master-the-moving-hold/)说明有生命感的停留。本案据此要求一个主动作、可读轮廓/注意对象，以及不夺走主意图的小变化。这是设计原则，不是把动物/IP 手势自动对应软件状态的权威字典；电影节奏或 UI 转场时长也不能冒充宿主播放设置。

## 保身份展示与角色依据
遵循[身份与展示](identity-and-presentation.md)。排版认可不等于角色美术通过。分别检查解剖、尾巴结构、合理遮挡、全部注意方向、代表封面索引与实际编码成品。每角色有自己的简洁依据与小巧思。保留批准变身和较新获准动作，不能跨未确认来源链迁移旧图缺陷或通过结论。这是视觉/制作要求，不是额外机器验收声明。
