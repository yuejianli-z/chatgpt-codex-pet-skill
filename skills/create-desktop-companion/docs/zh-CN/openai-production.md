# OpenAI 宠物独立制作与安装

本工具包不要求预装 `work-pets:pets`、`work-pets:create-pet` 或 `work-pets:update-pet`。我们借鉴三者的“管理选择／制作校验／保留 ID 更新”职责分离，独立提供 v2 图集组装、结构校验及源动作预览。仍需图像生成或编辑能力、Python 3.10+、Pillow 和经过确认的角色帧。账户权限、上传工具、OpenAI 应用本身并不随 Skill 提供。

## 四层不能混淆

1. 素材协议：图集格子、帧数、顺序。
2. 美术质量：身份一致、动作语义、透明边缘、自然衔接。
3. 展示预览：为了检查素材而选择的播放安排。
4. 应用运行：某个明确客户端及版本如何触发、循环、覆盖和中断。

九组素材不等于九种业务状态；十六向不是十六个任务状态。四向静态模型展示属于画册参考，不属于额外导入行。任何一层通过，都不能替代其他三层验收。

## 固定的 v2 规格

单张透明 PNG 或 WebP，必须精确为 1536 × 2288 像素；8 列 × 11 行，每格 192 × 208；不超过 20 MiB（20,971,520 字节）。原始生成图可以更大，但最终图集不能翻倍。用共同注册、正确比例和完整边界整理角色帧，不逐格拉伸或裁掉附属物。空白格 alpha 必须全为零，透明像素下的 RGB 不影响透明性。

| 协议行 | 动作键 | 固定帧数 | 预览每帧时长（毫秒） | 预览一轮 |
|---|---|---:|---|---:|
| 0 | idle | 6 | 280、110、110、140、140、320 | 1100 |
| 1 | running-right | 8 | 120 × 7、220 | 1060 |
| 2 | running-left | 8 | 120 × 7、220 | 1060 |
| 3 | waving | 4 | 140 × 3、280 | 700 |
| 4 | jumping | 5 | 140 × 4、280 | 840 |
| 5 | failed | 8 | 140 × 7、240 | 1220 |
| 6 | waiting | 6 | 150 × 5、260 | 1010 |
| 7 | running | 6 | 120 × 5、220 | 820 |
| 8 | review | 6 | 150 × 5、280 | 1030 |
| 9–10 | gaze | 16 张静态方向图 | 无内置显示时长 | 由鼠标及应用决定 |

共 57 张动作帧＋16 张方向图＝73 格有效内容，15 格透明空白。方向从屏幕正上方开始，每次顺时针增加 22.5°；第 9 行为 0°–157.5°，第 10 行为 180°–337.5°。这是注视，不是整体模型绕圈转身。本适配器只制作 v2；现有 v1 需要单独的旧版检查路线。

表中时长只用于源素材预览。已有一份桌面 26.1021.3705.0 的分析报告描述“待机减速六倍、非待机默认三轮后回待机，同时存在显式循环和注视覆盖”。这是有版本范围的报告，不是所有界面的通用保证，也不是图片能设置的参数。任务仍在运行，画面可能已回待机；不能用任务持续时间冒充动画实际停留时长。

## 没有官方三个 Skill 时如何完成

1. 确认目标宿主，取得角色基准和用户对身份、风格的认可。动物依据真实特征；已知 IP 检查同版本原始资料；概念角色用适合其结构的常见动作。
2. 按[出现频率与疲劳设计](exposure-design.md)规划动作，先确认设计再批量生成。
3. 同一身份参考分别生成九组动作条；用已确认的主方向锚点生成连贯的注视组。不要一次生成整张最终图集。保持固定帧数、共同尺度和识别点；提取完整姿势，不按不均匀源条机械等宽裁切。跳跃必须有实际离地位移；左右镜像不得改变非对称配件含义。
4. 整理成独立透明的 192 × 208 注册帧。检查原尺寸清晰度、透明边缘、自然遮挡、注视方向、动作循环及“待机→事件→待机”衔接。缺少绘图能力时不能伪造占位角色。
5. 用下述独立脚本组装并校验。它只复制原像素，不绘制、不缩放。结构通过不能证明解剖、身份、方向、动作疲劳或串入相邻格的内容正确，仍须目视验收。
6. 生成九组源动作预览和十六张方向图。实际解码查看，并按用户已确认的画册排版展示。展示排序可以调整，协议行序不能调整。
7. 给用户看最终形象和动态，记录这一确切版本的认可，再询问或执行已获授权的安装。

帧清单为 JSON：`actions` 必须包含上表九个键，每个键对应规定数量的相对帧路径；`gaze` 是按顺时针排列的十六个相对路径。应从真实帧库存生成完整清单，不放不存在的占位文件。

```sh
python -m pip install -r requirements.txt
python scripts/openai_pet_atlas.py build run/frames.json run/final/spritesheet.png
python scripts/openai_pet_atlas.py validate run/final/spritesheet.png
python scripts/openai_pet_atlas.py preview run/final/spritesheet.png run/source-preview
```

脚本独立检查 20 MiB，不假定上游校验器执行了所有文字规定；同时拒绝尺寸错误、格式错误、动画图集、有效格缺图和空白格不透明。不会覆盖已有导出文件。完整交付包含图集、源帧清单、结构报告、视觉验收、预览和宿主兼容说明；公开包默认不含用户私有参考照片。

## 验收后询问安装，已有授权不重复问

确认后询问：“要把这只宠物装上吗？当前支持的位置中，你希望用于 dot 头像、Work 宠物、桌面应用，还是多个位置？”只提供当前环境真实支持的目标。如果用户早已明确要求安装并激活到指定位置，就继续执行，不重复索要同一确认。认可外观不等于授权安装；只批准一个位置，不得修改其他位置或给助手改名。

- 新建：最终字节经过本地视觉门禁及可用的服务端预检后，用受支持的导入／创建路线执行一次，核对返回身份与名称。
- 更新已有角色：先唯一解析稳定 ID，再更新同一记录，不新建副本。名称可能重复，须分页核查；目标仍不明确才询问。保留未请求变更的名称、描述和当前选择。
- 仅改名称／描述：只改请求字段，不上传图集或重新生成。
- 激活：每个已授权目标分别选择对应 ID，并核对结果。共享素材库不等于选择自动同步或触发完全相同；未要求就不改 dot 名字。
- 上传会话：遵循当前工具说明，只用其支持的字节传输方式；临时上传地址不是宠物身份。验证确切字节，不复用过期会话；结果不确定先核查，不盲目重传或创建重复角色。
- 无可用写入路线：交付已校验 PNG/WebP、预览及该客户端已核实的导入步骤。没有完成当前服务端资格预检时，状态写“候选素材，导入资格未核验”；适用制作门禁和资格预检通过后才可写“可导入”，不能写“已安装”。安装我们的 Skill 不会自动获得不存在的 API 工具。
- 安装后：核对选择结果；确需电脑实测时取得对应访问权限，再检查外观与真实触发。分别记录已导入、已选中、视觉认可、实际运行验收，不为强行测等待或失败而制造危险操作。

`check_design_delivery.py --installation` 只检查流程决策，不执行外部写入，也不授予权限。

## 最终文件验收边界

随附 build/validate/preview 命令负责结构组装和源素材预览，不代替适用官方制作流程要求的完整门禁。新建或更新图集之前，还要对最终字节确认色边与透明度、结构连接、比例与位置、动作、方向语义及相邻方向连续性，并完成受支持的服务端资格预检。本地结构通过不能单独证明这些视觉属性或授权写入。预览命令产出的九个动作 GIF 和十六张静态图只是检查输入，不代表全部展示交付或实机测试已经完成。

更新前确认是可修改的自定义宠物；返回的稳定 ID 必须保持一致。创建或更新后回读列表，没有要求激活时保留原先选择；没有变化时不重复更新或切换。

流程检查记录可提供 final_artifact_sha256 以及 production_evidence、eligibility_evidence；两份证据都需 passed: true、匹配最终文件的 artifact_sha256 和非空 source。检查器不验证证据真伪；缺失或不匹配时返回 complete_final_preflight_before_authorized_operation，不推荐直接写入。
