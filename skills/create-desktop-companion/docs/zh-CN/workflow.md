# 执行工作流

[英文版](../en/workflow.md)为规范版本；本页保持语义一致。本流程用于规划与审阅伙伴项目；素材权利和宿主验收单独核对。

## 0. 制作前先核实目标平台

**R15 — 平台基石。** 在确定风格与动作预算前，明确目标产品、客户端/版本及接受的素材类型。记录当前权威格式/状态要求和证据，分清宿主硬约束、强制制作门禁、启发式诊断、预览设置、实际运行观察。缺证据的能力是**未知**，不能写成支持。概念制作可在明确集成缺口后继续；依赖该能力的导入/启用声明暂停。集成前阅读[平台基石](platform-foundation.md)并填写检查单。

本地质量错误不能证明服务端拒绝或内容禁忌。先保留批准原图与失败报告、分类原因，再决定是否修改。不能改随工具提供的门禁、删报告字段，或为过检查填满有意留白。强制门禁失败在受支持路径解决前仍阻止后续步骤。诊断用例能复现误报，不代表实际角色已合格。可展示、格式与制作就绪、已安装、实际验收必须分开，绑定确切作品和客户端版本。


## R01 — 接受普通输入并保留来源

从名字、原创文字、手机照、低清表情包、视频、多参考或已批准图集开始，不要求专业设定表。保留原始输入作为测试输入；研究补充证据，不能悄悄用精致参考替换它。通过实际看过的参考解决重要的名字/版本歧义，必要时只问一个聚焦问题。拼音译写不等于官方英文名。

记录输入类型、身份类别（个人宠物、既有角色、表情包/头像、原创、私有或未知）、来源/版本、实际可见事实及缺失视角。区分官方、社区维护、粉丝改绘、用户给定与推定证据。来源未知就保留未知。私人照片不默认获准上传第三方反向搜索。缺失背面属于设计推定，需要补造许可时先取得许可，不能称为已观察解剖。


公开既有角色默认至少收集三份同版本、实际查看且有不同身份/结构/动作价值的参考，不用重复图凑数。确实找不到时明确缺口并限制结论，不捏造证据或偷换版本。私人照片、原创设定及确无公开参考的对象不适用公开参考配额。

## R03 — 先选风格，再扩展制作

新建或实质改变风格时，默认提供三个可区分、控制变量的小样：身份、姿态、表情、镜头、服装语义一致，只改变风格。提供放大对照与真实目标显示尺寸。宿主尺寸未知时，提供64/96/128像素高的校准预览，标明是校准而非宿主实测。高分辨率母版不要求密集细节。

批量制作状态或方向前取得具体风格选择。未改风格的已批准基准直接复用，不重复询问。新风格选择只有在明确豁免这个角色、本次风格选择时才可代选；宽泛自主委托不取消后来具体的风格门。分别记录style、identity、outfit、pose和final批准范围。材质被认可不等于脸、比例和服装通过。按已选方向保留原比例CG、写实宠物、水墨、贴纸或软3D，不把所有角色变成大头玩具。

## R04 — 冻结最新相关批准基准

在私有项目记录中追踪参考版本/哈希、批准范围与用户证据。按当前任务相关的批准时间线解决冲突；较早安装的版本不自动优先。评估候选时重新打开同版本参考。以近似视角比较，不分别强拉等宽等高；说明归一化基准、锚点、遮挡与不确定性。面部/核心组件近景与原生尺寸全身是两项独立检查。

仅返修动作时，列明可改内容与受保护身份特征。不能为了运动方便更换下巴、比例、眼嘴、服装或配件。每个改动格都须经过[质量指南](quality.md)的身份门；未改格数量不能证明改动格通过。

## R05 — 两阶段执行与有限迭代

核实平台后，阶段一：识别研究→定义身份不变量与核心感觉→风格小样→一个获准基准。阶段二：复核宿主契约→检查已有动作行并按来源层级建立动作库→逐状态提出有依据的唯一表演供用户检查→写成具体简报→审阅代表动作的整轮语义区别→只扩展已批准的受影响状态/方向→检查最终导出→带限制交付。静态任务可在阶段一结束。

阅读[来源驱动动作设计](action-design.md)。语义重做不重新打开已批准外观；大范围改图前先展示动作映射，保留已有好动作与历史提示词。

必要时将用户判断合并到参考/身份、形象基准、代表动作三个节点。这是默认合并判断的上限式安排，不是强制三轮批准。可靠身份信息可让参考板仅作展示；已有批准不重复征求。仅在身份、范围或权限实质改变时再问。

每轮实验前写明一个主要缺陷、原因假设、保留项、可观察成功条件与小样预算。默认同一假设最多两次针对性局部尝试；这是成本控制预算，不是画质门槛。均无改善时更换证据、姿态约束、构图/建模或编辑路线。范围/成本实质变化须确认。记录缺陷→假设→有限改动→实测结果→保留/回退。保留最佳已批准版及失败记录。没有产物或未看过的产物仍是未验证。

## R07 — 完成交付范围，不夸大状态

读取当前宿主 schema。有日期边界的 Pets v2 为九轨 / 57 动作帧及 16 注视采样，与桌面四业务态分开。用户要求的身体视角是展示要求，不是宿主状态。真实动作、单体追视和要求的静态视角放在同一大板，用中英短标签，不堆底部长文。按最新核对布局确定尺寸，动画之外交代表帧总览和私有源包。未见视角细节明确标推断。见[身份与展示](identity-and-presentation.md)。

保留母版/源图集，另提供轻量聊天预览。对照母版检查预览覆盖、尺度、源帧索引时序与尾帧保持，而非只检查能打开。预览过大时制作轻量派生，保留母版。预览不能代替可导入图集；上传不等于运行验证；安装skill不等于创建或安装伴侣。

## R12 — 明确权限与发布边界

分别记录输出层级（概念、全套展示、可导入资产、已安装/宿主实测）与公开许可。可分发候选排除私人照片、角色作品、私有标识、历史提示词、凭据与许可不明资产。代码许可不授予角色/作品权利；用户承担IP风险不等于权利人许可。不保证版权无风险。准备项目文件不自动授权发布、上传、安装或外部传输。

执行门与证据边界见[质量](quality.md)和[多形态](multiform.md)。

用户请求大板时使用[面板标注](../../templates/zh-CN/action-board.md)：含义、选定动作、来源路线/改编、理由/区别、精确界面触发证据或未知、关键姿势或完整序列覆盖。注视样本单列方向标签，不计成额外任务状态。

保持请求的输出格式。用户要求或所给参考确定为动态大板时，不能以静态姿势表或静图轮播结束。关键姿势表标为阶段预览；最终编码动画须核验真实的状态内源动作后才能称完成。

用户授权按名单逐个制作时，按既定顺序逐角色推进。复用版式和标签习惯，不复用未经复审的角色动作。每个角色分别检查身份、三路来源、语义区别、真实源帧、文字及最终编码后再展示。后续授权只在其明确范围内取代早先的样版等待批准条件，不等于尚未完成的布局已验收，也不授权安装或发布。
