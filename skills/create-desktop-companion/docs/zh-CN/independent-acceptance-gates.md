# 相互独立的验收门

[English](../en/independent-acceptance-gates.md) | [简体中文](../zh-CN/independent-acceptance-gates.md)

以下是从实际测试中归纳出的通用经验。不附私人作品、原始照片、执行提示词、账户标识或作品哈希。此前否决的实验与后续获准的结果分别保留。两者都不证明全部原生运行场景，也不代表所有未来方案。

## 五道门分别取证

几何、身份、方向语义、完整覆盖和真实运行必须分别记录。这五类证据是必要条件，不足以证明动作设计已验收。还须对同一交付物完成[动作设计](action-design.md)中的整轮状态含义与跨状态对照审阅。不能用一项通过替代另一项。可安装格式与安装成功均比真实运行验收更窄，应依目标平台契约另记状态。

- **几何：** 使用未改动的官方结构、透明度、配准与质量检查。补充诊断不能代替官方门。
- **身份：** 在实际显示尺寸及不同底色下，核对已确认轮廓、比例、留白和多主体关系。
- **方向语义：** 每个注意方向都要可辨。手臂自然垂下不等于向下注视，躯干反转不等于仅头部转向。
- **完整覆盖：** 实际制作并审查全部必需方向与状态，还须检查接缝、变化连续性及冻结像素。四个基准方向不是十六方向；重复四帧不能增加覆盖。
- **真实运行：** 观察目标作品、客户端、状态进入、停留、中断与实际画面。本地预览、成功上传或服务端像素一致都不能证明宿主事件路由。

旧五字段补充脚本 `scripts/check_acceptance_scope.py` 只检查申报记录是否自洽，不代表完整语义验收；不验证证据真伪、所填方向集合是否符合平台、作品质量或宿主行为，也不授权安装。必需方向集合必须来自已核实的平台契约，不能为过检自行缩小。见[示例记录](../../templates/acceptance-scope.example.json)。

## 部分方向的可行性测试

只替换部分方向槽位的测试，只能说明这些槽位上的改动可行。它不能被当作完整的新序列：未改动的槽位仍是对照，整组失败或新旧槽位之间的不连续，也不是完整序列的测量。原有标准动作像素须全部保留。

由此得到两条经验：

- 局部诊断成功、身份、语义、完整覆盖与完整验收要分别判断。
- 填实原本刻意留白的形状，或移动伙伴的位置，即使空隙信号消失，也可能改变造型。没有眼嘴的实心形状，并不能保持空心头的身份。基准方向已被否决时，停止扩产。后来对其他改动的批准，不会追溯批准这组被否决的姿态。

## 自然遮挡与空隙诊断

自然姿态可能把较长的部件折到身体后方。官方提取可能通过，但未改动的空隙诊断仍会报告连续失败的行。遮挡部件可以减少信号，却可能遮住辨识度高的轮廓。分开的肢体和鞋子也会产生真实留白。

可行性测试不是完整图集的质量门。不得添加隐形填充、削弱检测器，或把错误数量减少称为通过。

## 多形态与状态起点

离线检查可以发现事件行中含有不同于主形态的像素，包括第零帧。形态语义来自目视审查，不能由哈希推断。服务端回读与原图一致，也不能说明实际客户端绘制了什么。

如果宿主确实绘制了正确的事件行帧，就不需要等到后续循环才显示替代形态。因此仅凭有限循环次数，不能解释状态开始时为什么从未看到替代形态。这只是条件推论，不是对宿主缺陷的诊断。

"忽略事件"与"注视绝对优先"两种模拟，可能从同一个文件得到只有主形态的输出，仅凭外观无法区分这两条路线。模拟器中的循环次数和帧延时只是测试假设，不是已核实的宿主策略。修改预览时序，不能修复尚未核实的事件选择。

**仍需证据：** 真实客户端观察，或受支持的遥测，确认选中了哪一行、何时绘制、被什么中断。在此之前，真实运行保持未知，已确认的源素材保持不变。

## 获准的可见填充

用户明确允许不透明的内部颜色时，应把它视为新的、限定范围的视觉约束，而不是修改验证器。用图像生成工具得到衬底，再把未改动的认可前景合成其上，使轮廓和伙伴的构图得以保留，而不是换成泛化的实心形象。

最终文件须运行未改动的完整质量门，并通过服务端预检。盲审的轴向判断只是对横向和纵向轴的观察，不证明所有相邻角度同样易辨。剩余的警告要保留，不能删除。

创建与存储回读可以核验。这并不证明该项已被选中，不证明它能在真实客户端播放，不证明长时间观看舒适，也不证明运行验收已完成。

## 最终文件与回读

先完成合成、清边和编码，再做最终门禁。每项门禁和审阅都要绑定到精确的最终文件。前版通过不能覆盖后续的绘制或合成。除几何外，必须检查最终美术像素。此后如果源图改变，要重新执行受影响的检查，旧结论不再有效。

回读时，编码 SHA-256 与解码 RGBA 结果分别记录。运行 `python scripts/compare_rgba.py final.png downloaded.png`。该比较器只接受单帧 8 位 RGB 或 RGBA PNG；遇到不支持的位深或动画时会拒绝，而不是静默比较转换后的首帧。它检查尺寸，以及每个 R、G、B、A 数值，包括 alpha 为零处的 RGB。

PNG 压缩或元数据不同、但解码像素一致，可以支持存储保真。仅文件哈希不同，不代表上传有问题。像素一致不证明实际运行。私人素材的哈希和下载文件，要留在方法包之外。

## 意义可能随时间漂移

一整行的动作含义，可能在后来的审查中发生变化，即使早先的审查已经通过。应复查整行，而不只是已经判断过的帧。只针对受影响帧的修正，是有限的动作含义修复，不是新的运行证明。其他状态仍须各自做语义判断，新的动作映射在检查和批准之前仍是提案。
